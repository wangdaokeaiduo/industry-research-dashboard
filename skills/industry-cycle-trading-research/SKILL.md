# 行业周期与左侧交易研究

## 核心原则

以证据链替代故事。明确事实、推断、假设和观点；所有动态数字标注口径、统计期、发布日期和来源链接。先研究产业，再研究价格；技术面不能推翻基本事实，只能辅助择时、仓位和失效点。

不得把波浪或缠论的主观划分伪装成唯一答案，不得只凭单一指标给出交易结论，不得承诺收益。数据不足时明确写“无法验证”，不要补造数字。

严格区分五个问题：行业景气是否改善、商业模式是否赚钱、估值是否有安全边际、技术位置是否适合交易、个股是否能兑现行业逻辑。任何一项不能直接代替另一项。

## 执行流程

### 1. 定义研究对象

- 明确行业、地区、时间点、投资期限和市场。默认研究中国市场、截至当前日期，并覆盖 3–6 个月交易视角与 1–3 年产业视角。
- 确定可交易映射：优先使用官方行业指数；没有合适指数时，构造 5–10 家有代表性的等权篮子，并披露成分与偏差。
- 判断类型：周期反转、成长景气、事件驱动或混合型。混合型分别建模。

### 2. 获取并核验真实数据

必须联网获取当前数据。完整遵循 [references/data-evidence.md](references/data-evidence.md)。先列数据需求，再搜一手来源；对核心供需与价格数据尽量双源核验。记录检索截止时间。

按行业建立最小数据集：

- 需求：销量、渗透率、开工率、订单、下游资本开支或消费量。
- 供给：产能、产量、库存、在建产能、淘汰/退出、进口与出口。
- 价格和利润：产品价、原料价、价差、成本、行业利润、现金流。
- 资本行为：资本开支、融资、扩产公告、并购、股东行为。
- 市场定价：指数和代表公司 OHLCV、估值分位、盈利预期修正。

### 3. 绘制产业链与竞争格局

阅读 [references/industry-research.md](references/industry-research.md)，完成上游—中游—下游价值链、关键瓶颈、议价权、技术路线、市场空间、竞争格局、代表公司映射与催化/风险清单。热门成长行业还要区分“需求真实增长”“份额迁移”“库存前置”“估值扩张”。

对可投资公司建立横向表，至少比较产品/份额、收入利润、现金流、资产负债、估值、催化剂和主要风险。输出“核心配置/成长弹性/反转观察/高风险”分层，不得把公司名单写成无条件荐股。

### 4. 判断周期阶段和反转条件

阅读 [references/cycle-reversal.md](references/cycle-reversal.md)。先定义该行业适用的领先、同步和滞后指标，再建立反转证据矩阵。每项必须写：方向、阈值、当前值、历史对比、是否达成、可信度、来源。

将阶段归为：繁荣后段、下行、出清、磨底、早期复苏、扩张、过热。给出主判断、备选判断及使主判断失效的证据。禁止用无依据的精确概率；若给概率，说明评分到概率的映射只是情景权重。

### 4.1 建立供需关系证据链

景气度之后必须单列“供需关系”，不得把收入增长直接等同于供需改善。分别检查需求、供给、库存、价格和利润五个维度，并给出“紧缺 / 趋紧 / 平衡 / 宽松 / 过剩”的状态与变化方向。

每个维度至少列一项带日期和来源的数据；库存缺失时明确写“无法验证”。结论必须回答：需求增长是否快于供给、库存由谁承担、价格是否有议价能力、利润改善来自销量还是价差。列出领先指标、改善阈值与证伪条件，并说明供需变化对行业利润和可交易资产的传导时滞。

### 4.2 汇总市场研报与机构预期

报告必须单列“市场研报与机构共识”，优先使用合法授权的券商研报、券商盈利预测、公司公告与用户提供的研报 PDF。Tushare `research_report` 是完整券商研报接口，`report_rc` 是券商盈利预测，`broker_recommend` 只是月度金股；三者不得混用或互相冒充。

研报处理必须去重并按机构、发布日期、分析师和覆盖对象标记。分别输出：样本数量、机构数量、共同观点、核心分歧、盈利预测上调/下调、市场已经定价的预期、原始研报链接和综合研判。综合研判不能拼接摘要；必须用产业供需、公司财报和官方数据逐项核验。未取得付费研报授权时不得绕过付费墙或推断正文，改为用户本地导入 PDF。

“市场研报”主列表必须以行业温度为目标，只展示行业周报、行业策略、产业专题、赛道研究和行业深度报告；不得混入个股点评或个股盈利预测标题。代表公司的券商盈利预测只能汇总为“行业盈利预期温度”，统计覆盖样本、上修/下修扩散和机构数量，不逐条占据行业研报列表。调用Tushare `research_report` 时强制使用 `report_type='行业研报'`。

行业研报模块必须进一步输出“共性与不同点”。共性不是简单合并摘要，而是列出至少两家独立机构共同支持的产业判断，并标注支持机构/报告数量和代表证据；不同点必须说明机构在需求、供给、价格、盈利、估值或节奏上的判断差异，以及差异对投资动作的含义。只有1份研报时只能写“单机构关注点”，不得称为共识；0份时明确写“样本不足”。只有标题时标记“标题级归纳、低置信度”，有摘要时标记“摘要级”，读过合法全文时才能标记“全文级”。最后形成一份独立综合判断，并用真实供需、财报、估值和K线验证，不得以机构数量代替事实。

免费来源优先使用券商官网公开研究、合法公开研报索引、世界银行和IMF开放报告库、McKinsey/BCG/Bain/Deloitte等公开行业洞察。巨潮资讯、交易所、国家统计局和行业主管部门只能标记为“事实核验”，不得伪装成券商研报。公开索引仅作为发现入口，引用时尽量回到原始机构页面；遇到登录、注册或付费限制时停止抓取，只保留合法入口。

### 5. 分析 K 线与左侧交易条件

获取复权方式一致的日线和周线 OHLCV，覆盖至少 250 个交易日；中长周期尽量取 3–5 年。若有 CSV，可运行：

禁止用相邻收盘价模拟开高低收蜡烛。缺少 OHLC 时只能绘制收盘价折线，并显式标记数据缺口。均线必须用完整历史计算后再截取可视窗口。

```bash
python3 scripts/analyze_ohlcv.py path/to/data.csv --lookback 120
```

完整遵循 [references/technical-left-trade.md](references/technical-left-trade.md)。依次分析：

1. 趋势、均线结构、相对强弱、缺口和关键支撑阻力。
2. 量能、换手、OBV、放量/缩量质量及价量背离。
3. MACD、RSI、ATR 等辅助指标，不机械套用超买超卖。
4. 波浪理论至少给出主计数与备选计数，并列失效点。
5. 斐波那契锚定清晰的主升/主跌波段，检验 0.382、0.5、0.618 等位置是否与其他结构共振。
6. 缠论标明所用级别，识别分型、笔、线段、中枢、背驰与一二三类买卖点；数据不足则降级描述。
7. 日周月多周期共振，并与基本面反转证据对照。

#### K线图强制可视化规则

- K线图必须显示清晰的价格纵轴刻度，不能只有蜡烛、均线和成交量而没有对应价格。
- 报告文字中出现的试仓位、突破触发位、加仓确认位、止损/失效位和重要支撑阻力，必须同步画成带数值标签的水平线；不得只在正文中写“突破 212.59”而让图上无法定位。
- 触发位与失效位使用不同颜色和线型，并直接标注“触发位 212.59”“失效位 172.01”等语义，不让用户依赖图例猜测。
- 图表纵轴范围必须包含当前可视窗口的 OHLC、均线和全部关键交易价位。即使关键位位于最近 50 日价格区间之外，也必须扩展纵轴将其显示。
- 缩放或拖动时间窗口后，价格轴和关键水平线必须继续正确显示；均线用完整历史计算，不能随可视窗口重新计算。
- 若文本无法得到明确、可复核的数值，不得虚构水平线，改为标记“价位待确认”。

### 6. 形成可执行但有边界的结论

把左侧价值分为“不适合 / 观察 / 试仓 / 条件性加仓”，不要简单输出“买/卖”。同时给出：

报告JSON必须使用结构化交易等级，不得让前端从自然语言猜测：`no_trade`（不适合交易）、`data_insufficient`（关键数据不足）、`wait_trigger`（等待触发）、`trial`（小仓试错）、`add`（条件性加仓）。局部数据缺口应另列 `dataGaps`，不能因为某一个行业指标没有统一口径，就把整份报告判成“数据不足”。

- 支持证据与反对证据。
- 已达成、部分达成、未达成的反转条件。
- 触发条件、失效条件、观察指标和下一次验证时间。
- 仓位采用分批与风险预算语言；不替用户假定风险承受能力。
- 区分产业观点、指数观点和个股观点，避免从行业景气直接跳到个股必涨。

### 7. 建立决策系统与周度复盘

完整阅读 [references/investment-decision-system.md](references/investment-decision-system.md)。每份报告必须包含：

- 投资决策总览：产业价值、商业质量、估值吸引力、技术位置、综合评级和核心矛盾。
- 与上周比较：不只重写文章，还要记录指标、条件状态、评级和触发/失效点的变化。
- 公司分层与筛选：披露口径、排除条件和最大风险。
- 盈利与估值情景：公开乐观/基准/悲观假设、计算式和可验证变量，不给无依据目标价。
- 催化剂日历：日期、事件、市场预期、实际结果和影响。
- 执行与风险预算：当前动作、触发条件、加仓条件、价格失效、基本面失效、最大观察期和下次复核日。
- 空头辩护与证据质量：三个最强反对理由、与主判断冲突的数据、可推翻结论的证据和数据等级。

## 输出格式

按以下顺序输出：

1. 是否可以交易：直接给“不适合 / 观察 / 试仓 / 条件性加仓”，随后写理由、现在怎么做、触发后怎么做、加仓条件与退出条件。
   - 禁止只写“等待触发”。必须在顶部同屏写明具体价格、量能标准、基本面确认项和价格认错位。
   - 顶部必须同步展示K线判断：趋势状态、均线关系、量能状态、技术评级以及它如何改变当前动作。
   - 交易等级由基本面、估值和技术面共同决定。基本面决定是否进入交易池，真实OHLCV决定试仓/加仓时点和失效位；技术面不得掩盖基本面恶化。
2. 投资决策总览与核心矛盾。
3. 本周变化与评级调整原因。
4. 行业景气度、周期阶段与反转证据。
5. 供需关系：需求、供给、库存、价格、利润及传导时滞。
6. 市场研报与机构共识：共识、分歧、预期修正和事实核验。
7. 真实数据仪表盘、产业链与利润分配。
8. 公司横向比较、投资分层与排除清单。
9. 盈利拆分、估值情景和关键敏感性。
10. 板块及代表公司的真实 OHLCV 与多体系技术分析；价格轴和交易关键位必须可视化。
11. 基本面—估值—技术面共振。
12. 催化剂日历、乐观/基准/悲观情景。
13. 执行方案、风险预算、价格与基本面失效。
14. 空头辩护、数据缺口、证据等级和来源。

结论中明确说明数据截至何时。引用应紧贴对应事实，不要把全部链接堆到文末。
