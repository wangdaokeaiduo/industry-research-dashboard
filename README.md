# 周期信号 · 行业研究终端

一个面向 A 股行业研究的本地可视化网站。报告以 JSON 文件保存，网站自动读取并动态展示行业景气度、供需关系、周期位置、反转条件、公司比较、估值、研报共识和技术面交易计划。

项目默认附带猪周期、游戏、医美、白酒、旅游酒店、光模块、MLCC、黄金、创新药和医药连锁十份示例研究报告。报告仅用于研究与信息展示，不构成投资建议。

**作者：王导可爱多**

## 这个项目可以用来做什么

它不是只看K线的行情页面，也不是自动荐股软件，而是一套“行业基本面研究—市场定价—交易执行”工作台，适合完成以下任务：

- 判断猪肉、白酒、酒店、化工等周期行业正处于下行、出清、磨底、复苏还是过热阶段。
- 研究游戏、光模块、MLCC、机器人、半导体等成长行业的需求是否真实、供给是否紧张、利润能否兑现。
- 把行业新闻、官方数据、公司财报、券商研报和市场行情放进同一条证据链，减少只看单篇研报造成的偏差。
- 跟踪反转条件已经完成几项，哪些仍未发生，以及什么数据会推翻当前判断。
- 用代表公司或官方指数构建板块篮子，通过真实OHLCV、量能、均线、波浪、斐波那契和缠论辅助择时。
- 在报告最前方得到明确行动方案：当前是否可交易、触发什么、突破价格、量能要求、如何试仓、何时加仓、哪里认错。
- 每周重写同一行业报告，观察景气、估值、研报温度和交易条件是否发生变化。
- 将其他软件生成的标准JSON报告直接导入网页阅读，不需要数据库和云服务。

典型提问示例：

```text
调研猪肉板块现在处于猪周期的哪一步，列出反转条件的完成情况。
分析MLCC行业景气度、供需、A股映射、估值和左侧交易价值。
研究光模块行业，汇总行业研报共性与分歧，并用真实K线给出触发条件。
更新白酒板块周报，只保留最新报告，并说明本周发生了什么变化。
```

## 最快使用方法

只想阅读现有报告，不更新数据：

```bash
git clone https://github.com/wangdaokeaiduo/industry-research-dashboard.git
cd industry-research-dashboard
npm install
npm run dev
```

浏览器打开 `http://localhost:5173`，在左侧选择行业即可。仓库已经包含十个行业的JSON数据，不配置任何密钥也能使用。

## 主要功能

- 最前方直接展示是否具备交易条件、触发价格、量能要求、加仓条件和失效位
- 行业景气度、周期阶段与反转条件跟踪
- 供给、需求、库存、价格和利润的交叉验证
- 代表公司财务、估值和产业链暴露比较
- 真实前复权 OHLCV 行情与板块等权篮子
- 5、10、20、60、90、145 日均线及量能分析
- K 线悬停价格、最近 50 个交易日窗口和左侧拖动缩放
- 波浪理论、斐波那契、缠论及通俗技术面解读
- 行业研报共性、差异和整合结论
- 监控 `data/reports/`，JSON 更新后网页自动刷新

### Skill 具体约束

- 动态事实必须带日期、口径和来源，核心供需数据优先使用一手来源并尽量双重核验。
- 数据不足时写“无法验证”或列入 `dataGaps`，不能补造数字。
- 行业研报主列表只放行业周报、策略、专题和行业深度，不把个股研报冒充行业温度。
- 研报共识至少需要两家独立机构；只有单一机构时必须降低置信度。
- 必须使用真实OHLCV，不能用相邻收盘价模拟K线。
- 行业基本面决定是否进入交易池，技术面只决定试仓、加仓和失效时点。
- 所有交易结论必须同时写触发条件和证伪条件，不输出收益承诺。

完整执行规范见 [`SKILL.md`](skills/industry-cycle-trading-research/SKILL.md)，数据、周期、产业链、技术面和投资决策细则位于其 [`references`](skills/industry-cycle-trading-research/references/) 目录。

## 怎样阅读一份报告

建议按照页面顺序阅读，不要先跳到个股名单：

1. **是否可以交易**：先看 `no_trade`、`data_insufficient`、`wait_trigger`、`trial` 或 `add`，再看具体触发价、量能和认错位。
2. **行业景气度**：回答行业是在改善还是恶化，以及改善来自真实需求、补库存、涨价还是低基数。
3. **周期和反转条件**：查看每项条件是已达成、部分达成还是未达成，避免用一句“行业反转”替代证据。
4. **供需关系**：分别看需求、供给、库存、价格和利润，判断增长最终能否转化为企业利润。
5. **公司比较与估值**：区分行业受益纯度、盈利质量和市场已经计入的乐观预期。
6. **行业研报**：重点看多家机构共同支持的事实、存在分歧的变量，以及综合判断有没有被真实数据验证。
7. **技术面**：看当前价与20/60/90/145日线、量比、关键水平线和多周期结构；技术面不能覆盖基本面失效。
8. **执行方案**：只在预先写明的条件出现时调整动作，同时遵守价格和基本面两类失效条件。

### 五个交易等级

| 等级 | 含义 | 常见动作 |
| --- | --- | --- |
| `no_trade` | 基本面、估值或趋势不支持交易 | 回避，等待研究条件变化 |
| `data_insufficient` | 关键事实或行情无法核验 | 补数据，不根据猜测操作 |
| `wait_trigger` | 产业逻辑存在，但价格或盈利尚未确认 | 观察明确触发位，不追涨 |
| `trial` | 基本面进入交易池，量价出现初步确认 | 按风险预算小仓验证 |
| `add` | 突破、回踩、盈利和供需形成共振 | 满足预设条件后分批处理 |

## 导入自己的行业报告

把 UTF-8 JSON 文件放入 `data/reports/` 即可，运行中的网站会自动加载。最小结构：

```json
{
  "id": "industry-id",
  "industry": "行业名称",
  "category": "cycle",
  "asOf": "2026-08-11",
  "updatedAt": "2026-08-11T12:00:00+08:00",
  "summary": {},
  "cycle": {},
  "reversalConditions": []
}
```

完整字段参见 [`data/report.schema.json`](data/report.schema.json)，写入规范参见 [`REPORT_FORMAT.md`](REPORT_FORMAT.md)。推荐先写临时文件，完成后再原子重命名为 `.json`，避免网站读取到未写完的数据。

## 常见问题

### 不配置Tushare能不能使用？

可以。现有报告和网站均可正常打开；只有重新拉取行情、财务、估值或研报数据时才需要Token。

### 为什么有些行业显示“数据不足”？

这意味着影响结论的关键数据无法从合法、可追溯来源获得。局部缺口应该列在 `dataGaps`，只有缺口足以阻止交易判断时才使用 `data_insufficient`。

### 为什么报告经常是“等待触发”？

`wait_trigger` 必须同时给出等待的具体内容，例如“收盘突破306.58且成交额达到20日均额1.2倍”，不能只有模糊的“等待”。行业景气改善并不自动代表当前价格适合买入。

### 为什么板块价格不是某只股票的价格？

没有合适官方指数时，报告会把5–10家代表公司前复权并标准化，形成等权篮子。该点位用于衡量板块整体趋势，不是任何一只股票的成交价格；报告必须披露篮子成分和偏差。

### JSON写入后页面没有更新怎么办？

先确认文件位于 `data/reports/`、扩展名为 `.json`、编码为UTF-8且包含必填字段；再查看终端是否报告结构校验错误。推荐先写临时文件，完成后再重命名为正式文件。

### 如何每周覆盖更新？

让Codex读取上次JSON，对比本周数据并写回同一个文件即可。保持相同 `id` 和文件名，就会覆盖旧报告而不是新增重复行业。

## 数据口径与免责声明

- 行情和财务数据需核对数据源、复权方式、截至日期及样本成分。
- 板块篮子可能包含产业链公司，不等同于交易所正式行业指数。
- 技术分析是概率判断，触发位与失效位不能保证收益。
- 公开研报摘要不能替代原始研报全文和公司公告。
