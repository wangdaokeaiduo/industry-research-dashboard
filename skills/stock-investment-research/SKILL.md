# 个股投资研究

## 边界与路由

- 研究对象是一个明确证券或上市公司时执行本 Skill。
- 用户同时给出行业和个股时，以个股为主执行本 Skill，并调用行业结论作为公司外部环境，不生成行业篮子代替个股行情。
- 用户只问行业、板块、产业链或多个公司横向筛选时，停止本 Skill，改用 `industry-cycle-trading-research`。
- 名称存在歧义时先通过交易所或行情源确认证券代码、上市地和币种。

## 核心约束

### 深度研究硬门槛

默认每一次个股请求都是完整深度研究，不因用户只写股票名、只说“技术分析”或连续查询多只股票而降级。只有用户明确说“只看某一模块、不要完整报告”时才允许缩减。

交付前必须同时完成：公司业务与产业位置、公司专属经营变量、最新年度/季度/业绩预告、财务三表和现金流质量、债务与资本开支、近90日公告消息、五年审计风险、行业供需、同业比较、盈利估值情景、机构共识与分歧、催化剂、真实OHLCV技术面、介入/加仓/失效条件、空头辩护和数据缺口。不得用通用行业文字、模块数量或几项财务指标冒充公司深度研究。

报告只有通过深度审计后才能设置 `researchDepth: full`。缺少任一核心证据链时保持未完成并继续检索；无法取得时写明无法验证及其对结论的影响。去重只允许跳过“指纹相同且 `researchDepth` 为 `full`”的报告；旧版或浅层报告即使指纹相同也必须重做。

必须联网取得最新资料。事实、计算、推断和假设分别标记；动态数据写明统计期、发布日期、来源和访问日期。优先使用交易所公告、定期报告、公司官网、监管文件和原始行情，媒体和社交平台只作线索。

不得把新闻标题、机构目标价、资金流标签、波浪或缠论单独作为买入理由。不得承诺收益。数据不足时写“无法验证”，不得生成虚假OHLC、公告、财务指标或精确价位。

无论用户说“技术分析”“消息面”“能不能买”还是“投资价值”，默认交付都必须是完整深度研究，用户明确要求只看某一模块时才能缩减。不得先生成技术专项快报冒充完整报告，也不得以响应速度为由省略基本面、财务三表、估值、近90日公告、行业供需、催化剂、审计风险、同业比较和预期差。

## 工作流

### 1. 确认证券与研究窗口

- 确认公司全称、代码、交易所、币种、复权口径和最新交易日。
- 默认覆盖1–3年公司逻辑、3–6个月交易视角、至少250个交易日的日线；有条件取3–5年。
- 识别公司收入对应的行业环节，必要时读取现有行业报告，但不得从行业景气直接推导公司必涨。

### 2. 建立基本面证据链

完整读取 [references/fundamental-news.md](references/fundamental-news.md)，检查：

- 产品与收入结构、客户和地区暴露、竞争壁垒、份额及商业模式。
- 最近年度和季度的收入、利润、毛利率、费用率、ROE、经营现金流、资本开支、净负债、存货、应收与合同负债。
- 利润增长来自数量、价格、份额、成本、汇率、补贴还是一次性项目。
- 管理层指引、产能、订单、研发、股权激励、分红、回购、增减持和质押。
- 使用至少一家可比公司或历史区间校验估值，不用单一PE下结论。
- 单独列出最近5个完整年度的财报审计风险：审计意见、审计机构、签字会计师、审计费用、机构变更、关键异常、风险等级和解除条件。标准无保留意见只能说明当年审计结论，若后来发生会计差错更正、监管问询或非标意见，必须说明其对历史报表可信度的追溯影响。

出现审计保留意见、财务造假调查、债务违约、重大诉讼、退市风险、持续经营疑虑或无法解释的现金流背离时，设置风险否决或显著降级。

### 3. 研究消息面与预期差

- 先查交易所公告和公司原文，再查监管、行业数据和可信媒体。
- 对近90日重要事件建立表格：日期、事件、事实、来源、市场预期、可能影响、是否已在价格中反映、下一验证点。
- 在使用最新季报数字前，必须调用或检索 `forecast`、`express` 和交易所业绩预告/快报；若公告日晚于季报，顶部盈利结论、情景和交易否决必须优先使用最新预告，并用“累计预告减已披露季度”推算隐含单季区间，明确标记为计算值。不得让旧季报覆盖更新的盈利信息。
- 将消息分成：基本面改变、估值/资金催化、短期情绪、噪音、重大风险。
- 相同消息多平台转载只算一条；传闻必须标为未证实，不能写成事实。
- 判断“利好但股价不涨”或“利空但不跌”的预期差，同时检查成交量和相对行业强弱。

### 4. 获取真实行情并分析技术面

完整读取 [references/technical-entry.md](references/technical-entry.md)。获取统一复权口径的真实日线和周线OHLCV，不少于250日。均线使用完整历史计算，再截取最近50日显示。

至少分析：

- 5、10、20、60、90、145日均线，趋势、支撑阻力、缺口与相对强弱。
- 当日量能相对5、10、20、60、90、145日均量；换手率、OBV和量价背离能取得时一并检查。
- MACD、RSI、ATR仅作辅助。
- 波浪给主计数、备选计数和失效位；斐波那契公开锚点；缠论注明级别和替代划分。
- 图表显示价格纵轴、悬停OHLC、最近50日、可拖动缩放，并绘制带数值标签的触发、加仓和失效水平线。

技术面必须单独形成结构化模块，不得只输出一段笼统文字。固定顺序为：

1. 趋势结构：把近期行情拆成筑底、启动、回踩、主升或派发等阶段，列出时间区间、价格区间与量价特征。
2. 均线系统：逐项展示 MA5、MA10、MA20、MA60、MA90、MA145 的数值、价格关系和支撑/压力含义，同时计算短期乖离。
3. 核心指标：至少给出 MACD、KDJ、RSI、BOLL 的真实数值、状态与相互验证；超买不等同于立即见顶，需结合趋势和量能解释。
4. 量价与筹码：给出当日成交量/额相对 5、10、20、60、90、145 日均量；筹码集中度、获利比例等只有真实接口可得时才展示，否则明确写“数据不足”和缺失原因。
5. 多空清单：分别列出支持上涨和提示风险的证据，避免只讲单边逻辑。
6. 通俗结论：明确说明目前处于什么阶段、追高/回踩/突破哪一种更合适、触发区间、量能门槛和失效位；若基本面或治理触发否决，必须说明技术强势不能覆盖该否决。

所有指标均标注数据截止日与复权口径。实时行情晚于日线接口时，可以用可追溯的实时行情补齐当日K线，但必须标记来源，并避免把尚未更新的估值字段写成 `NaN`。

### 5. 判断投资价值

分别给出并解释：

1. 行业与公司产业位置。
2. 商业质量和治理质量。
3. 盈利趋势与现金流质量。
4. 估值安全边际与市场隐含预期。
5. 消息催化及其可信度。
6. 技术位置、量能和风险收益。

综合等级只能使用：

- `no_trade`：基本面恶化、重大风险或无法定义损失边界。
- `data_insufficient`：证券或关键数据无法核验。
- `wait_trigger`：具备研究价值但技术、盈利或消息确认不足。
- `trial`：基本面至少一项领先信号和量价信号确认，可小仓试错。
- `add`：盈利与趋势持续确认，可条件性加仓。

### 6. 给出可执行介入方案

顶部直接回答“现在是否可以介入”，同屏写明：

- 当前结论和一句核心理由。
- 当前价、趋势、均线和量能状态。
- 首次介入的明确价格或区间、收盘/盘中口径、量能倍数、基本面或公告确认项。
- 加仓条件：突破回踩、盈利兑现、现金流或行业数据确认。
- 价格失效位、基本面失效条件、最大观察期和下次复核日期。
- 风险仓位只给公式：`风险仓位上限 = 单笔允许损失占比 / 介入价至失效价跌幅`，不替用户假设账户规模。

## 输出顺序

1. 是否可以介入：结论、理由、现在怎么做、触发后怎么做、加仓与退出。
   - 顶部结论不得由 `decisionLevel` 映射成“等待触发/现在不追”等固定套话；`decisionLevel` 只用于风险颜色和动作分组。
   - 必须生成 `tradeDecision`：`asOf`、针对该证券当前状态的 `verdict`、由数据推导的 `reason`，以及 `checks[]`。每个检查项必须含 `name/current/threshold/status`，其中 `status` 只能为 `met/partial/unmet`。
   - 检查项至少覆盖实际收盘价与突破线、当日成交额相对20日均额、MA20与MA60/145位置、MACD/RSI/KDJ过热状态；完整个股报告还要覆盖盈利、现金流、审计或治理否决项。
   - 页面必须直接显示“达成数/总数”、实际值、门槛和未达成项。同为 `wait_trigger` 的不同证券，应因主要瓶颈不同而显示不同结论，例如“趋势转强但量能差确认”或“仍在弱势区且量能不足”。
   - 若价格和量能已触发但审计、治理或盈利存在一票否决，必须写成“量价已触发，但××风险否决”，不得退化为笼统的“不适合介入”。
2. 投资价值评分：产业位置、商业质量、盈利现金流、估值、消息、技术。
3. 公司业务与竞争优势。
4. 最新财务、盈利拆分和质量检查。
5. 最近5个完整年度的财报审计风险与解除条件。
6. 估值：历史、可比公司、乐观/基准/悲观情景，不给无依据目标价。
7. 近90日公告与消息：事实、影响、预期差和验证点。
8. 结构化技术分析：趋势、均线、指标、筹码边界、多空信号、综合研判、K线与交易验证。
9. 基本面—估值—消息—技术共振矩阵。
10. 催化剂、三个最强空头理由、证伪条件和数据缺口。
11. 数据截止日和紧贴结论的来源链接。

## 网站与JSON交付

项目包含 `data/reports/` 网站时必须执行：

- 生成前执行幂等去重：以证券代码、复权口径、最新完整交易日OHLCV、最新财报/业绩预告/快报和生成器版本形成稳定指纹。若目标报告的 `generationFingerprint` 相同，返回 `skipped_duplicate`，不得重写JSON、Markdown、更新时间或重复创建页面；只有任一输入或模板版本变化，或用户明确要求强制重写时才生成。
- 上述去重还必须要求现有报告 `researchDepth: full` 且通过完整性审计；浅层、旧版或最新事件未进入顶部结论的报告不得跳过。

- 把用户确认的每项功能、报告结构、字段口径、数据边界、页面交互、自动化与启动方式同步固化到对应Skill；不得只修改代码或单份报告。更新后同步工作区Skill与本机已安装Skill，运行Skill格式校验并纳入版本控制。

- 把个股研究放入独立的“个股研究”选项卡，不与板块报告混排；板块继续使用 `industry-cycle-trading-research`。
- 生成或覆盖 `<ticker>-stock.json`，设置 `reportType: stock`，公司名作为 `industry` 展示字段。
- 保留 `decisionLevel`、`executionPlan`、`sources`、`technical.ohlc`、`technical.volumeAverages` 和 `technical.technicalDetail`。
- `technical.technicalDetail` 固定包含 `asOf`、`headline`、`structure`、`movingAverages`、`indicators`、`marketStats`、`chip`、`signals`、`plainConclusion`；页面按六段展示，并移除重复的旧技术解读卡片。
- 新增 `auditRiskHistory`：包含 `period`、`overallRisk`、`summary`、`watch` 和最近5年 `items`。每项至少包含 `year`、`annDate`、`opinion`、`agency`、`signers`、`fee`、`risk`、`riskLabel`、`change`、`issue`。
- 页面把审计风险放在真实财务数据之后、估值之前；列表突出非标意见、事务所变更和风险解除条件。没有审计数据时写“无法验证”，不得默认无风险。
- K线默认显示最近50个交易日，支持左右拖动、悬停OHLC/成交额，并绘制带价格数值的触发位和失效位。
- 每次研究或重写个股都必须同步生成网站可读取的JSON和Markdown，不得只在聊天中返回文字；确认本地API和“个股研究”选项卡已经出现该报告，缓存未刷新时重载或重启本地服务。
- 默认交付与打开的界面必须是主站“个股研究”选项卡，使用 `?report=<report-id>#technical` 直达对应个股技术面；不得用独立HTML代替主站交付，独立诊断页只能作为内部辅助验证，不自动弹出给用户。
- 新增个股时优先复用参数化生成器（证券代码、名称、行情代码、行业报告），不要复制一份只适用于单只股票的生成脚本；但交易措辞必须根据价格位于MA20上方或下方动态生成，禁止把“尚未站上均线”误写成“回踩均线”。
- 当收盘位于MA20上方0%–3%且当日成交额低于20日均额0.8倍时，识别为“缩量回踩MA20观察区”，不得写成“追涨”或“放量突破”；左侧触发至少要求止跌K线、重新站上MA5和量能恢复，右侧触发仍要求突破位与≥1.2倍量能共同确认。
- 交付前对每份个股报告执行模块完整性审计：供需、消息面、催化剂、同业比较、估值情景、空头理由、证据等级、审计历史、技术详情和数据缺口。任一核心模块未调用时报告不得标记完成；数据源确实无权限时说明缺口并用其他合法一手来源交叉核验，页面不得显示只有标题的空模块。
- 催化剂必须有日期或明确时间窗口，并标注“已披露/交易所预约日/待确认”。优先调用 `disclosure_date` 获取定期报告预约日，调用 `forecast` 和 `express` 获取业绩预告/快报；再从交易所公告原文提取股东大会、解禁、回购、重大项目等日期。不得把推测日期写成确定事件。
- 消息面优先调用交易所公告全文和公司原文；接口未接入或无权限时生成显式数据边界，不用媒体转载数量冒充公告覆盖。必须调用 `daily_basic`、`fina_indicator`、财务三表与可比公司数据生成估值和盈利情景；除非用户明确要求只做单一模块，否则不得以“技术专项”为理由省略。
- 检查供需关系不得出现无解释的 `—`：个股缺少直接供需指标时，调用对应行业报告提供行业需求、供给、库存、价格、利润，并明确区分行业事实、公司验证指标和无法验证项。
- 检查JSON不得出现 `NaN`、虚构筹码或错误继承的板块单位；运行测试、生产构建和浏览器视觉检查后再交付。
- 成交额必须在进入图表前统一换算为“百万元”：Tushare `daily.amount` 原始单位为千元，换算除以1000；实时接口若返回元则除以1,000,000。交付前用换手率×流通市值或成交量×均价做数量级交叉检查。
- 价格失效位必须低于当前收盘价；若算法产生高于现价的支撑/止损位，视为数据错误并拒绝交付，应改用最近结构低点或现价下方的有效支撑。
- 实时接口在未开盘、集合竞价前、盘中或数据源延迟时可能返回新日期的不完整快照。日线指标只使用完整收盘K线：上海时区当日15:00前的实时日K不追加，盘中价只可单独标注，不进入均线、量比和指标计算。15:00后仍须满足开、高、低、收、成交额全部为有效正数，且 `high >= max(open, close)`、`low <= min(open, close)`；若OHLC四值完全相同且成交额低于近20个完整交易日均额的1%，仍视为集合竞价/未完成快照并拒绝追加。不通过时使用上一完整交易日。
- 项目提供深度报告审计脚本时必须纳入每次文档生成流程；审计至少强制检查完整模块、真实OHLC不少于250根、5/10/20/60/90/145六档量能、交易判定不少于5项，并拒绝残留“仅作技术研究/需另行完整研究”的报告进入网站。
